PythonのFlask環境構築手順（Mac）

Flaskを使うための環境を構築する手順を 仮想環境（venv）を利用する方法 で説明します。


         # Pythonのバージョン確認
         python3 --version

         # プロジェクト用のディレクトリを作成（例: my_project）
         mkdir my_project && cd my_project

         # 仮想環境の作成（venv は好きな名前に変更可能）
         python3 -m venv venv

         # 仮想環境を有効化
         source venv/bin/activate

         # 仮想環境の無効化（終了）
         deactivate

         # Flaskをインストール
         pip install flask

         # Flaskのバージョン確認
         python -m flask --version

         # Flaskアプリの作成
         touch app.py

         # app.py に以下のコードを記述
         from flask import Flask

         app = Flask(__name__)

         @app.route("/")
         def home():
             return "Hello, Flask!"

         if __name__ == "__main__":
             app.run(debug=True)

         # Flaskを起動する前に、環境変数を設定
         export FLASK_APP=app.py
         export FLASK_ENV=development  # デバッグモードを有効化

         # Flaskアプリの起動
         flask run  # Running on http://127.0.0.1:5000/

         # 必要なパッケージを追加 (任意)
         pip install flask-sqlalchemy flask-wtf flask-login

         # 依存関係を記録・再現
         pip freeze > requirements.txt
         pip install -r requirements.txt

         # プロジェクトのフォルダ構成（推奨）
         my_project/
         ├── venv/               # 仮想環境
         ├── app/
         │   ├── __init__.py     # アプリの初期化
         │   ├── routes.py       # ルーティング
         │   ├── templates/      # HTMLテンプレート
         │   ├── static/         # CSS, JS, 画像
         ├── app.py              # メインのエントリーポイント
         ├── requirements.txt    # 必要なパッケージ
         ├── run.py              # アプリの起動用スクリプト

Python の __init__.py（イニットパイ）役割

Django の場合

  • パッケージの識別
    • myproject/ や myapp/ をパッケージとして扱うために __init__.py を配置する。
  • 初期化処理
    • __init__.py にコードを書けば、パッケージがインポートされたときに実行されます。 
    
                         # mypackage/__init__.py
                  print("mypackage が読み込まれました")
               
                  import mypackage
                         # 実行結果: mypackage が読み込まれました
  • モジュールのエクスポート
    • __init__.py に __all__ を定義すると、from package import * でインポートできるモジュールを制御できる 
    
       ディレクトリ構造

         mypackage/
         │── __init__.py
         │── module1.py
         │── module2.py
         mypackage/__init__.py

         #mypackage/__init__.py
            print("mypackage が読み込まれました！")
         #Pythonコード


       import mypackage

→ 実行すると mypackage が読み込まれました！ と表示される。
  • 結論：
    • Python プロジェクトに必須ではない（Python 3.3 以降）。
    • ただし、明示的なパッケージ管理 や サブパッケージを扱う 場合は __init__.py を入れたほうがよい。
    • チーム開発や整理されたプロジェクトでは、__init__.py を使うのが一般的。

✅ __init__.py を置くと、そのフォルダは「Python のパッケージ」として認識される
❌ __init__.py を置いても、それ自体が「Python プロジェクト」として認識されるわけではない
✅ パッケージ化すると、import してモジュールを管理しやすくなる
つまり、「Python プロジェクト全体を定義するものではなく、あくまでその部分を「パッケージ」として認識させるためのファイル」

Flask の場合

Flask は Django ほど厳格なディレクトリ構造を要求しませんが、大規模なプロジェクトでは __init__.py を使って アプリのファクトリー関数 を定義します。 Flask プロジェクト構造（例） 

      flask_project/
         │── myapp/
         │   ├── __init__.py   # Flask アプリの初期化
         │   ├── routes.py
         │   ├── models.py
         │   ├── static/
         │   ├── templates/
         │── run.py            # アプリを実行するスクリプト

Flask における __init__.py の役割

アプリケーションの初期化（アプリファクトリー） __init__.py に Flask アプリを作成する処理を記述し、他のモジュールと連携できるようにする。 

         # myapp/__init__.py
         from flask import Flask

         def create_app():
            app = Flask(__name__)
            app.config.from_object('config.Config')  # 設定を読み込む

            # ルートを登録
            from .routes import main
            app.register_blueprint(main)

            return app
これにより、run.py から create_app() を呼び出してアプリを作成できる。

Blueprint（ブループリント）を登録

Flask では機能を分割するために Blueprint を使うことが多い。 例えば routes.py にルートを定義し、それを __init__.py で登録する。 


# myapp/routes.py
from flask import Blueprint

main = Blueprint('main', __name__)

@main.route('/')
def home():
    return "Hello, Flask!"
   -~~~~~
# myapp/__init__.py
from flask import Flask

def create_app():
    app = Flask(__name__)

    from .routes import main
    app.register_blueprint(main)

    return app

結論

フレームワーク	__init__.py の主な役割
Django	プロジェクトやアプリを パッケージ化 し、必要に応じてアプリ設定を定義

Flask	アプリファクトリー を作成し、アプリの初期化や Blueprint を登録

小規模な Django / Flask プロジェクトでは __init__.py に何も書かないこともありますが、
パッケージとして認識させるために必要 なので、必ず配置するのが一般的です。
